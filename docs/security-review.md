# Security review

Phase 09 checked each rule of the "Security" section of `docs/spec/BUILD.md`, and the
extra items of the security review in `docs/spec/prompts/09-hardening.md`. For each rule,
the table names the code that applies it and the test that checks it.

"Done" means: the code applies the rule, and an automated test or a check of a packaged
build (see the notes under the table) shows it.

## Extra items of prompt 09

| Rule                                                                                                          | File                                                                                                                                                                                                                                                                                                               | Status |
| ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------ |
| No `nodeIntegration: true`, `contextIsolation: false`, `sandbox: false`, or `webSecurity: false` in the code. | None found in `src/`. `test/unit/web-preferences.test.ts` reads every `webPreferences` object in `src/` and fails on these and other unsafe values.                                                                                                                                                                | done   |
| The import is untrusted input: it has the size limit.                                                         | `src/main/config-transfer.ts` (`MAX_IMPORT_BYTES`, 256 KB). The limit applies to the file, the pasted text, and the unpacked text form. `src/main/import-window.ts` reads at most 256 KB and 1 byte of a file. Tests: `test/unit/config-transfer.test.ts`.                                                         | done   |
| The import checks each value.                                                                                 | `src/main/config-transfer.ts` (`GENERAL_FIELDS`, `ACCOUNT_FIELDS`, and a reader for each value). A wrong value makes the whole import unreadable. Tests: `test/unit/config-transfer.test.ts`.                                                                                                                      | done   |
| The import takes no file path or URL from the import.                                                         | `src/main/config-transfer.ts` has no path or URL field. The only file path comes from the open dialog. An imported address goes into Google's sign-in URL only as an encoded query value (`signInUrl` in `src/main/google-urls.ts`). It goes into the `mailto:` link of "Email it to myself" only percent-encoded. | done   |

## Notes

1. Fuses. `CSC_IDENTITY_AUTO_DISCOVERY=false npx electron-builder --dir` on macOS (after `npm run build`), then `npx @electron/fuses read --app dist/mac/Shifted.app`, shows `RunAsNode` disabled, `EnableCookieEncryption` enabled, `EnableNodeOptionsEnvironmentVariable` disabled, `EnableNodeCliInspectArguments` disabled, `EnableEmbeddedAsarIntegrityValidation` enabled, and `OnlyLoadAppFromAsar` enabled. The packaged app starts. Windows and Linux builds use the same configuration, but this review did not build them.
2. Remote debugging. The packaged macOS app, started with `--remote-debugging-port=9333`, answers nothing on that port. The same command with the development build opens the port, so the check works.

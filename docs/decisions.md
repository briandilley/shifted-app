# Decisions made during the build

## Phase 00: bootstrap

- **App version 0.1.0.** The spec gives no version. Nothing is released yet, so the version starts below 1.0. The user agent token is `Shifted/0.1.0`.
- **User agent token placement.** Electron puts its own app token (`shifted/<version>` or `Shifted/<version>`) in the default user agent. `src/main/user-agent.ts` removes that token and puts `Shifted/<version>` right before `Chrome/`, where Electron puts its app token. All other tokens, including `Electron/<version>`, stay as Electron made them. If the default user agent has no `Electron/` token, the function throws, so a dishonest user agent cannot ship by mistake.
- **Test server paths.** The spec gives only the Gmail example (`<server>/gmail/`). The other URL functions use the paths of the fake server: Calendar `<server>/calendar/`, sign-in `<server>/signin`, and feed `<server>/feed/atom/<label>`.
- **Feed labels are already in URL form.** `feedUrl(label)` adds the label as it is, for example `%5Esq_ig_i_personal`. Prompt 04 gives the labels in that form.
- **User data folder for tests.** Each end-to-end test sets the environment variable `SHIFTED_USER_DATA_DIR` to its own new temporary folder. The main process calls `app.setPath('userData', ...)` with it before anything else. This is the simplest way to give each test its own state.
- **Fake sign-in button.** The "Sign in" button of the fake `/signin` page is a form that posts to `/signin`. The server answers with a `Set-Cookie` header (`FAKE_SID`) and a redirect to `/gmail/`. The fake page needs no script.
- **Content Security Policy in development.** The production page uses a strict policy with no `'unsafe-inline'`. The Vite development server adds styles with `<style>` tags. It also uses a WebSocket for hot reload. So, in development only, a small Vite plugin adds `'unsafe-inline'` to `style-src` and `ws://localhost:*` to `connect-src`.
- **Preload script.** The template's `@electron-toolkit/preload` gave the page the whole `ipcRenderer`. It is removed. The preload script gives the page one empty, frozen object, `window.shifted`. Later prompts add functions to it.
- **Main window navigation.** Prompt 03 adds the link rules. Until then, the screens of Shifted open no new window. They also do not go away from their own page. Shifted always refuses a certificate error.
- **Strict TypeScript.** The shared base configuration from `@electron-toolkit/tsconfig` turns `noImplicitAny` off. Each project configuration sets `strict: true` and `noImplicitAny: true` again. `npm run typecheck` also checks the tests, with `tsconfig.test.json`.
- **Minimal electron-builder configuration.** `electron-builder.yml` has the app ID, the product name, the icon folder `build/`, and an AppImage target for Linux. The template's snap and deb targets, its placeholder update URL, and its prebuilt `.icns` and `.ico` files are removed. electron-builder makes the icon files from `build/icon.png`. Prompt 10 adds installers.
- **Prettier and ESLint ignore `docs/spec/`.** The spec copy is read-only, so a formatter must not change it. The React lint rules apply only to `src/renderer/`, because Playwright fixtures also use a function named `use`.
- **End-to-end tests run one at a time** (`workers: 1`), because each test starts its own Shifted.

## Phase 01: one account

- **The account is saved when it is made.** "Add account" writes the new account to `config.json` at once, before sign-in ends, because the prompt says that Shifted makes the account first. If the sign-in window closes before sign-in ends, Shifted removes the account again.
- **"Signed in once" is not saved.** An account that is in `config.json` when Shifted starts counts as signed in once, so closing its sign-in window later shows "This account is signed out." and does not remove it. This needs no new field in the configuration. The cost: if Shifted quits during the first sign-in and the removal cannot end, the account shows as signed out at the next start. To make this rare, Shifted waits for running removals before it quits (`will-quit`).
- **Account colors.** The fixed set of 8 colors is in `src/main/config.ts`. A new account gets the color after the color of the last account in the order, and the first account gets the first color. Prompt 02 can change the set.
- **A broken configuration file.** A file that is not JSON, has another `version`, or has a wrong field anywhere counts as broken. Shifted copies it to `config.broken.json` and writes a new empty `config.json` at once. An account `id` must be a UUID, because it goes into the partition name and the folder name.
- **Atomic write.** Shifted writes `config.json.tmp` with synchronous file calls, then renames it to `config.json`. The file is small, and synchronous writes cannot overlap.
- **Where the Google page shows.** Each React screen tells the main process the bounds of the element where the Google page goes (`setViewBounds`), and the main process puts the `WebContentsView` there. So the CSS alone decides the height of the top line of the sign-in window and of the temporary bar of the main window.
- **The sign-in window.** It is 480 by 720 points of content (`useContentSize`), its title is always `Sign in`, and it is not a child of the main window. If a page in it asks for a new window, the page loads in the sign-in window, and Shifted opens no new window and never the default browser (rule 3 of "Links").
- **When sign-in ends.** Shifted checks the URL on `did-navigate` of the sign-in page, so only a committed main-frame page counts. `isGmailUrl` in `google-urls.ts` checks the origin `https://mail.google.com` and a path that starts with `/mail/u/`. Then Shifted writes the cookies of the session to disk (`cookies.flushStore()`) before it closes the sign-in window.
- **Signed-out check.** The Gmail view stops a main-frame `will-navigate` and a main-frame `will-redirect` to `accounts.google.com`. The check needs `will-redirect`, because Gmail sends a signed-out session to the sign-in page with an HTTP redirect. Frames inside Gmail can still load pages of `accounts.google.com`. If you click Google's own "Sign out" inside Gmail, Shifted also stops that page and shows the signed-out panel. Prompt 02 adds "Sign out" to the context menu.
- **Gmail opens no new window yet.** Until prompt 03 adds the link rules, the Gmail view refuses every new window, and links that open a new window do nothing.
- **The temporary bar.** The main window has a bar at the top with the account address (or "New account" before Shifted reads the feed), its color, and "Remove account". "Add account" shows only when there is no account, because this phase shows one account. Prompt 02 replaces the bar with the sidebar.
- **The remove confirmation.** It is a native message box with "Remove" and "Cancel"; "Cancel" is the default. End-to-end tests replace `dialog.showMessageBox` in the main process to answer it.
- **Feed request.** Shifted reads the feed with `session.fetch(..., { credentials: 'include' })`, because Electron sends no cookies by default. It reads the feed after each load of Gmail and saves the address only when it changed.
- **Fake sign-in and sign-out.** The fake sign-in sets `FAKE_SID` to a new random session ID with `Max-Age` of one year. A cookie with no expiry date does not persist after a restart, so the restart test needs it. The fake server keeps the valid session IDs. The control route `POST /control/sign-out` ends every fake session, and the next request of a session gets a response that clears its cookie. Like Google, the fake `/signin` goes straight to `/gmail/` for a session that is signed in, and the fake feed answers 401 for a session that is not.

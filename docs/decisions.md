# Decisions made during the build

## Phase 00: bootstrap

- **App version 0.1.0.** The spec gives no version. Nothing is released yet, so the version starts below 1.0. The user agent token is `Shifted/0.1.0`.
- **User agent token placement.** Electron puts its own app token (`shifted/<version>` or `Shifted/<version>`) in the default user agent. `src/main/user-agent.ts` removes that token and puts `Shifted/<version>` right before `Chrome/`, where Electron puts its app token. All other tokens, including `Electron/<version>`, stay as Electron made them. If the default user agent has no `Electron/` token, the function throws, so a dishonest user agent cannot ship by mistake.
- **Test server paths.** The spec gives only the Gmail example (`<server>/gmail/`). The other URL functions use the paths of the fake server: Calendar `<server>/calendar/`, sign-in `<server>/signin`, and feed `<server>/feed/atom/<label>`.
- **Feed labels are already in URL form.** `feedUrl(label)` adds the label as it is, for example `%5Esq_ig_i_personal`. Prompt 04 gives the labels in that form.
- **User data folder for tests.** Each end-to-end test sets the environment variable `SHIFTED_USER_DATA_DIR` to its own new temporary folder. The main process calls `app.setPath('userData', ...)` with it before anything else. This is the simplest way to give each test its own state.
- **Fake sign-in button.** The "Sign in" button of the fake `/signin` page is a form that posts to `/signin`. The server answers with a `Set-Cookie` header (`FAKE_SID`) and a redirect to `/gmail/`. The fake page needs no script.
- **Content Security Policy in development.** The production page uses a strict policy with no `'unsafe-inline'`. The Vite development server adds styles with `<style>` tags. It also uses a WebSocket for hot reload. So, in development only, a small Vite plugin adds `'unsafe-inline'` to `style-src` and `ws://localhost:*` to `connect-src`.
- **Preload script.** The template's `@electron-toolkit/preload` gave the page the whole `ipcRenderer`. It is removed. The preload script gives the page one empty, frozen object, `window.shifted`. Later prompts add functions to it.
- **Main window navigation.** Prompt 03 adds the link rules. Until then, the screens of Shifted open no new window. They also do not go away from their own page. Shifted always refuses a certificate error.
- **Strict TypeScript.** The shared base configuration from `@electron-toolkit/tsconfig` turns `noImplicitAny` off. Each project configuration sets `strict: true` and `noImplicitAny: true` again. `npm run typecheck` also checks the tests, with `tsconfig.test.json`.
- **Minimal electron-builder configuration.** `electron-builder.yml` has the app ID, the product name, the icon folder `build/`, and an AppImage target for Linux. The template's snap and deb targets, its placeholder update URL, and its prebuilt `.icns` and `.ico` files are removed. electron-builder makes the icon files from `build/icon.png`. Prompt 10 adds installers.
- **Prettier and ESLint ignore `docs/spec/`.** The spec copy is read-only, so a formatter must not change it. The React lint rules apply only to `src/renderer/`, because Playwright fixtures also use a function named `use`.
- **End-to-end tests run one at a time** (`workers: 1`), because each test starts its own Shifted.

## Phase 01: one account

- **The account is saved when it is made.** "Add account" writes the new account to `config.json` at once, before sign-in ends, because the prompt says that Shifted makes the account first. If the sign-in window closes before sign-in ends, Shifted removes the account again.
- **"Signed in once" is not saved.** An account that is in `config.json` when Shifted starts counts as signed in once, so closing its sign-in window later shows "This account is signed out." and does not remove it. This needs no new field in the configuration. The cost: if Shifted quits during the first sign-in and the removal cannot end, the account shows as signed out at the next start. To make this rare, Shifted waits for running removals before it quits (`will-quit`).
- **Account colors.** The fixed set of 8 colors is in `src/main/config.ts`. A new account gets the color after the color of the last account in the order, and the first account gets the first color. Prompt 02 can change the set.
- **A broken configuration file.** A file that is not JSON, has another `version`, or has a wrong field anywhere counts as broken. Shifted copies it to `config.broken.json` and writes a new empty `config.json` at once. An account `id` must be a UUID, because it goes into the partition name and the folder name.
- **Atomic write.** Shifted writes `config.json.tmp` with synchronous file calls, then renames it to `config.json`. The file is small, and synchronous writes cannot overlap.
- **Where the Google page shows.** Each React screen tells the main process the bounds of the element where the Google page goes (`setViewBounds`), and the main process puts the `WebContentsView` there. So the CSS alone decides the height of the top line of the sign-in window and of the temporary bar of the main window.
- **The sign-in window.** It is 480 by 720 points of content (`useContentSize`), its title is always `Sign in`, and it is not a child of the main window. If a page in it asks for a new window, the page loads in the sign-in window, and Shifted opens no new window and never the default browser (rule 3 of "Links").
- **When sign-in ends.** Shifted checks the URL on `did-navigate` of the sign-in page, so only a committed main-frame page counts. `isGmailUrl` in `google-urls.ts` checks the origin `https://mail.google.com` and a path that starts with `/mail/u/`. Then Shifted writes the cookies of the session to disk (`cookies.flushStore()`) before it closes the sign-in window.
- **Signed-out check.** The Gmail view stops a main-frame `will-navigate` and a main-frame `will-redirect` to `accounts.google.com`. The check needs `will-redirect`, because Gmail sends a signed-out session to the sign-in page with an HTTP redirect. Frames inside Gmail can still load pages of `accounts.google.com`. If you click Google's own "Sign out" inside Gmail, Shifted also stops that page and shows the signed-out panel. Prompt 02 adds "Sign out" to the context menu.
- **Gmail opens no new window yet.** Until prompt 03 adds the link rules, the Gmail view refuses every new window, and links that open a new window do nothing.
- **The temporary bar.** The main window has a bar at the top with the account address (or "New account" before Shifted reads the feed), its color, and "Remove account". "Add account" shows only when there is no account, because this phase shows one account. Prompt 02 replaces the bar with the sidebar.
- **The remove confirmation.** It is a native message box with "Remove" and "Cancel"; "Cancel" is the default. End-to-end tests replace `dialog.showMessageBox` in the main process to answer it.
- **Feed request.** Shifted reads the feed with `session.fetch(..., { credentials: 'include' })`, because Electron sends no cookies by default. It reads the feed after each load of Gmail and saves the address only when it changed.
- **Fake sign-in and sign-out.** The fake sign-in sets `FAKE_SID` to a new random session ID with `Max-Age` of one year. A cookie with no expiry date does not persist after a restart, so the restart test needs it. The fake server keeps the valid session IDs. The control route `POST /control/sign-out` ends every fake session, and the next request of a session gets a response that clears its cookie. Like Google, the fake `/signin` goes straight to `/gmail/` for a session that is signed in, and the fake feed answers 401 for a session that is not.

## Phase 02: many accounts

- **The new color set.** The 8 colors of prompt 02 replace the colors of phase 01. Shifted stores them as the prompt writes them (`#1A73E8`, upper case) and compares colors without regard to case. An account from phase 01 keeps its old color until you change it.
- **The next color.** With `n` accounts, a new account gets color `n mod 8` of the set. If an account already uses that color, Shifted takes the first color after it that no account uses. So 8 accounts in a row get the 8 colors in order, and the set repeats after 8. This rule does not depend on the order in the sidebar, so a drag does not change the next color, and a removal does not give two accounts the same color when a free color exists.
- **The order values.** After each move, the accounts get the order values 0, 1, 2, and so on, from top to bottom.
- **Drag uses pointer events.** The sidebar follows the pointer with `pointerdown`, `pointermove`, and `pointerup`, not with HTML drag and drop. The list shows the new order while you drag. A press that moves less than 5 points is a click. Alt+Up and Alt+Down also move the focused account, for people who do not use a mouse.
- **The text when you point to an account.** It is the native tooltip of the account button (the `title` attribute), with the nickname on one line and the address on the next. The sidebar is only 68 points wide, and the view of the Google app covers anything that React draws to the right of it. A native tooltip shows above the view.
- **The account name before Shifted reads the feed.** The sidebar and the configuration window say "New account". The avatar letter is the first letter of the address. If the account has no address yet, it is the first letter of the nickname, and with no nickname the avatar shows only the color.
- **The selected account at start.** It is the first account in the sidebar. Shifted does not save the selected account.
- **Views are made when they show.** At start, Shifted makes only the view of the Google app that the selected account used last. Each other view is made the first time it shows. One exception: after a sign-in ends, Shifted also makes the Gmail view of that account, even if the account is not selected, so that it reads the address and the photo. Prompt 07 decides what loads in the background.
- **Status names.** The status `gmail` of phase 01 is now `signed-in`, because it now covers Gmail and Calendar. A Calendar view that goes to Google's sign-in page also shows the signed-out panel.
- **The tab bar** shows the two tabs for the selected account in every status. In the signed-out panel, a tab click only changes the Google app that shows after sign-in.
- **The profile photo lookup.** `gmail-page.ts` looks for the image in the account button: first `a[href*="SignOutOptions"] img` (the same in every language), then `img.gbii`, then `a[aria-label^="Google Account"] img`. Gmail draws its page after the load event, so the script looks again every 0.5 seconds for up to 30 seconds. If the image has a `srcset`, the script takes its largest image. Shifted looks up the photo each time Gmail loads.
- **The photo download.** Shifted downloads only from an `https:` URL on `googleusercontent.com`, `gstatic.com`, or `google.com` (in test mode, from the fake server). The check is `isProfilePhotoUrl` in `google-urls.ts`, so that Shifted sends traffic only to Google. It asks for PNG or JPEG, refuses more than 5 MB, and converts the image with `nativeImage` to a 96 by 96 PNG. If the Gmail page shows no photo, Shifted keeps the photo that it saved before.
- **The photo on screen.** The main process sends each saved photo to the screens as a `data:` URL in the state. The strict Content Security Policy already allows `data:` images, so the screens need no access to files.
- **Photos after Sign out and Remove.** Sign out keeps the saved photo. Remove deletes it with the session.
- **The context menu** is a native menu. Rename opens the account page with the focus in Nickname. Color opens it with the focus on the selected color. Notifications opens the account page. Sign out is off while the account is not signed in. Sign out asks for no confirmation, because the account stays and you can sign in again.
- **Sign out.** Shifted closes the sign-in window and the views of the account, then calls `clearStorageData()`, `clearCache()`, and `clearAuthCache()` on its session and writes the cookies to disk. The partition folder stays. "Sign in again" waits until the session is clear.
- **The configuration window.** Shifted has at most one. It is 720 by 520 points and is not a child of the main window. Cmd+, opens it at General. If it is already open, Cmd+, brings it to the front and keeps its page. The context menu always switches it to the page of the account. If an account is removed while its page shows, the window shows General.
- **Changes save at once.** The nickname saves at each key press. Shifted saves it without spaces at the start and end, and keeps at most 100 characters. A color saves when you click it.
- **The empty pages.** General and Notifications show only their heading in this phase.
- **The application menu.** Cmd+, needs a menu item, so Shifted now sets its own small menu: the app menu on macOS (or File on Windows and Linux) with "Settings" (`CmdOrCtrl+,`, `CommandOrControl+,` since phase 07) and Quit, then Edit, View (zoom and full screen), and Window. The menu has no Reload item. Prompt 07 adds Cmd+R for the Google app.
- **Fake accounts.** The fake sign-in page has an Email field, filled with `test@example.com`. Each sign-in starts a session for the address in the field, so each account of Shifted, with its own cookie, sees its own address in the fake Gmail, the fake Calendar, and the fake feed. The fake Calendar also sends a signed-out session to `/signin`. The control route `POST /control/sign-out` still ends every session.
- **The fake photo.** The fake Gmail page has an account button `<a href="/SignOutOptions"><img class="gbii" src="/avatar.png"></a>`. `/avatar.png` is a PNG square in a color made from the address of the session.
- **Native menus in end-to-end tests.** Playwright cannot click a native menu or press a key that only a native menu handles. The tests replace `Menu.prototype.popup` in the main process, keep the menu, and click its item. For Cmd+, the test clicks the "Settings" item of the application menu and checks that its accelerator is `CmdOrCtrl+,` (`CommandOrControl+,` since phase 07).

## Phase 03: links

- **Rule 3 comes first in the sign-in window.** `routeNavigation` checks rule 3 before rules 1 and 2 when the request comes from the sign-in window. Rules 1 and 2 are about the Google apps of an account, and sign-in ends only when the sign-in window itself reaches Gmail. In the sign-in window, every `http:` and `https:` page stays, and a new window loads in the sign-in window (as in phase 01). A `mailto:` link and a new window on `about:blank` are blocked there, so nothing leaves the sign-in window.
- **What a Gmail pop-out is.** A new window that the Gmail view or a child window opens on a Gmail page, or on `about:blank`, is a Gmail pop-out and opens in a child window (rule 4). A navigation of the Gmail view to a Gmail page stays in the Gmail view, and a navigation of a child window to a Gmail page stays in the child window. Gmail pop-outs use many URL forms (`view=pt`, `view=lg`, `popout`, `about:blank`), so Shifted does not try to tell them apart from other Gmail links in a new window. A Gmail link from the Calendar view selects the Gmail tab (rule 1).
- **Calendar opens no child window on a Calendar page.** A navigation of the Calendar view to a Calendar page stays. A new window that Calendar opens on a Calendar page loads in the Calendar view (rule 2). A new window on `about:blank` from Calendar opens a child window, like one from Gmail.
- **Gmail and Calendar links.** `isGmailLink` and `isCalendarLink` in `google-urls.ts` check the host only: `https://mail.google.com` and `https://calendar.google.com`, with any path. `http:` URLs on these hosts go to the default browser. In test mode, they check the path on the fake server: `/gmail/` and `/calendar/`.
- **Google's redirect page.** Gmail sends some links in messages through `https://www.google.com/url?q=<target>`. If the target is a Gmail or Calendar link, Shifted routes the target, and loads the target in the Gmail or Calendar tab. For every other target, the default browser gets the original URL, so Google's link check still runs. In test mode, the redirect page is `<server>/url`.
- **Only the main frame is routed.** `will-navigate` handles only main-frame navigations. Frames inside a Google page, for example Google Chat in Gmail, load freely, because Gmail needs them.
- **Signed-out check in one place.** The check that stops Google's sign-in page (phase 01) moved into `link-handlers.ts`. It runs in `will-navigate` and `will-redirect` of the Gmail view, the Calendar view, and each child window, before the link rules.
- **The tab of the same account.** For `gmail-tab` and `calendar-tab`, Shifted selects the account (also if the request comes from a child window of an account that is not selected), selects the tab, saves it as the Google app that the account used last, loads the URL in the view, and brings the main window to the front.
- **`mailto:` reloads Gmail.** For now, a `mailto:` link loads the Gmail compose URL in the Gmail view of the same account, as the prompt says. This loads Gmail again. Shifted also denies the `openExternal` permission (see below), so Chromium never hands a `mailto:` link to the operating system.
- **Child windows.** A child window is a normal window, not attached to the main window. Its size comes from the `window.open` features of the page (Electron's default is 800 by 600). Its title is "Shifted: " and the address of the account (the nickname, or "New account", if the address is not known yet). The page cannot change the title, and the title changes when the address or the nickname changes. A child window closes with its opener page, which is Electron's default. When an account is removed, signed out, or found signed out, Shifted destroys its child windows, so a page cannot keep them open.
- **Empty child windows close.** A page can open a child window on `about:blank` and then send it to another place. If the link rules send that place out of the child window (for example to the default browser) while the child window still shows nothing, Shifted closes it. A child window that opened on a URL that turned into a download, and showed no page, also closes. A child window that opened on `about:blank`, for example pop-out compose, never closes for a download.
- **One answer for the camera and the microphone.** The permission `media` covers both, as the prompt groups them. The question is a native message box that names the account and the permission, with "Allow" and "Don't allow". "Don't allow" is the default button and the cancel button, so Escape denies. Shifted saves every answer, including a denial. Two requests at the same time share one question.
- **Permission checks.** The permission check handler grants `notifications`, and an asked permission only with a saved "allow". A check never asks.
- **Every other permission is denied.** As the spec says, this includes `clipboard-sanitized-write` (writing the clipboard with the async clipboard API), `fullscreen`, `speaker-selection`, and `openExternal`. If a "Copy" button of Gmail or Calendar, or full screen video, does not work in a manual test, the spec rule is the cause.
- **Screen sharing asks first on every platform.** A test on Electron 45 showed that `getDisplayMedia` goes to the permission request handler as `display-capture` before the display media handler. So Shifted asks before any picker, also with the macOS system picker. The display media handler checks the answer again. On macOS before version 15, the system picker is not there, and Electron calls the handler, so Shifted shows its own picker. Shifted shares video only, no system audio.
- **Linux with Wayland.** Shifted treats Linux as Wayland when `XDG_SESSION_TYPE` is `wayland` or `WAYLAND_DISPLAY` is set. There, it calls `desktopCapturer.getSources`, the desktop portal shows its own picker, and Shifted shares the one source that comes back.
- **The Shifted screen picker** is a small window (600 by 520 points) with the screens and the windows as buttons with a picture, and a Cancel button. Escape and closing the window share nothing. Only one picker is open at a time. A second request while it is open shares nothing.
- **New configuration fields.** The configuration has `general.askWhereToSave` (false by default) and, for each account, `pagePermissions` (the saved answers). The version stays 1. A file from phase 02 has neither field, and Shifted reads it with the defaults. An unknown permission name or a wrong value makes the file broken, like any other wrong field.
- **The account page** shows the saved answers ("Camera and microphone: Allowed") above "Reset page permissions". The button is off when there is nothing to reset.
- **Download names.** Shifted uses the last part of the name that Chromium suggests. While a download runs, its name stays reserved, so two downloads at the same time never get the same name. With "Ask where to save each file" on, the save dialog starts in the Downloads folder with a name that is not taken. The notification has the title "Download finished" and names the file and the folder. Shifted keeps each notification object until it closes, so that its click still works.
- **The test hook** is `globalThis.shiftedTestRecords` in the main process, with `openExternal`, `showItemInFolder`, and `downloadNotifications`. The end-to-end tests read it with `electronApp.evaluate`, and click a download notification with `emit('click')`. In test mode, Shifted still shows the download notification.
- **The fake download starts on a Gmail page.** Like a Gmail attachment, the fake download is at `/gmail/attachment`, so the link rules keep it in Shifted. A download link outside Gmail goes to the default browser by rule 5.
- **macOS entitlements.** `build/entitlements.mac.plist` now also has `com.apple.security.device.camera` and `com.apple.security.device.audio-input`. A signed build with the hardened runtime needs them for the camera and the microphone, in addition to the usage descriptions in `mac.extendInfo`.

## Phase 04: unread badges

- **The XML parser.** `fast-xml-parser` (version 5) is a runtime dependency. `parseFeed` checks the XML with its validator first, and keeps every value as text, so that a subject such as "2026" stays a string. A feed must have a `<feed>` root with a whole-number `<fullcount>`. Anything else is a parse error.
- **The feed request uses `net.request`, not `session.fetch`.** A test on Electron 45 showed that the response of `session.fetch` has an empty `url` after a redirect, and that `redirect: 'manual'` makes it throw. So Shifted could not see a redirect to the sign-in page. `src/main/session-fetch.ts` sends the request with `net.request` and the cookies of the session, and keeps the URL of each redirect. If any redirect goes to the sign-in page, the read counts as "signed out", also when the sign-in page sends the request on to another page. A request stops after 30 seconds, and Shifted reads at most 5 MB. This replaces the "Feed request" choice of phase 01.
- **Error results and tooltips.** HTTP 401 or 403, or a redirect to the sign-in page: "Signed out". A network error or a timeout: "Offline". Shifted does not try to tell "offline" apart from other network errors. Another status that is not 200: "Gmail answered with an error (HTTP 500)". An answer that is not a feed: "Gmail sent something that is not a feed".
- **The address comes only from the "Whole inbox" feed.** The spec gives only the title `Gmail - Inbox for <address>`. The title of a label feed (Primary, Important) can have another form, so Shifted does not read the address from it. Shifted still reads the "Whole inbox" feed after each load of Gmail for the address, as in phase 01. The fake label feeds have the title `Gmail - Label '<label>' for <address>` on purpose, so that a test fails if Shifted depends on it.
- **The Gmail title.** `parseInboxTitle` in `gmail-page.ts` accepts only `Inbox (N) - <address> - Gmail` and `Inbox - <address> - Gmail`. N can have separators, for example `1,234`. Gmail writes its title in the language of the account, so for an account in another language "Automatic" never makes a choice and keeps "Primary". The configuration override covers this case. Gmail sets its title after the load event, so Shifted waits up to 30 seconds for a `page-title-updated` event that shows the inbox. If Gmail shows a message and not the inbox, Shifted tries again on the next load.
- **The saved automatic choice.** The configuration has two new fields for each account: `unreadCountSource` ("automatic" by default) and `automaticFeed` (`"primary"`, `"whole-inbox"`, or `null`). The version stays 1. A file from phase 03 has neither field, and Shifted reads it with the defaults. After "Automatic" saves a choice, Shifted stops comparing. If you choose "Automatic" again in the configuration, Shifted forgets the saved choice and learns it again: at once if Gmail of the account already shows, otherwise on the next load of Gmail. An override (Primary, Whole inbox, Important) keeps the saved automatic choice.
- **Polling.** When Shifted starts, and when you add an account, the first read waits a random 0 to 5 seconds. After that, each read waits 60 seconds plus a random 0 to 5 seconds. After 1, 2, and 3 or more errors in a row, the wait is 60 seconds, 2 minutes, and 5 minutes, plus the random delay. A good read resets it. A read when you switch to an account starts the wait again. Shifted also reads the feed of an account after its sign-in ends, after Sign out, after a change of "Unread count source", and when Shifted finds the account signed out. Shifted does not read the feed of a new account while its first sign-in runs, so a new account shows no badge until sign-in ends.
- **Unread counts stay in memory.** Shifted does not save them on disk. After a start, the badges show nothing until the first read. After a failed read, Shifted keeps the last count in memory but shows only the warning mark, and the account adds nothing to the app badge.
- **The sidebar badge.** The count is a red pill on the top right corner of the avatar, with "99+" for more than 99. The warning mark is an amber circle with "!". Its tooltip is the native tooltip of the mark (`title`), with the reason only, for example "Signed out". The tooltip of the account button stays the nickname and the address. Screen readers get the count or the reason through `aria-describedby`, so the accessible name of the account does not change.
- **The app badge.** macOS gets the full number, for example "120", as the prompt says "with the number". The Windows overlay shows "99+" for more than 99, like the sidebar, because the image is small. Shifted draws the overlay as a 32 by 32 pixel red circle with white digits from a 3 by 5 pixel font, and shows it at 16 by 16 points (scale factor 2). Its description is "N unread". Linux gets `app.setBadgeCount`. Shifted changes the app badge only when the total changes. The overlay also goes on a new main window (macOS `activate`).
- **The configuration field.** "Unread count source" is a drop-down list on the account page, below Color. A short note under it says what "Automatic" does now, or that an override counts the unread messages of one feed.
- **The fake feeds.** The fake server keeps a count and entries for each feed, either for one address or for every address with no own value. `POST /control/feed` sets them (`server.setFeed`). The fake server takes the feed labels from `FEED_LABELS` in `google-urls.ts`. The fake Gmail title follows the Primary count of its address and, like Gmail, shows no number for 0 (`Inbox - test@example.com - Gmail`). `POST /control/feed-failure` (`server.setFeedFailure`) makes every feed answer HTTP 500. It can also make every feed redirect to the fake sign-in page, so that a test covers the "Signed out" case.
- **The test hook** `globalThis.shiftedTestRecords.appBadgeTotal` holds the total of the app badge, so that the end-to-end tests check the sum on every platform. On macOS, the test also checks `app.dock.getBadge()`.

## Phase 05: notifications

- **Quiet hours: a daily range and days that are quiet all day.** PRODUCT.md says that quiet hours are "a daily time range and a set of weekdays with no notifications". Its example is "quiet outside 9:00 to 18:00, Monday to Friday". So the range applies every day, and each chosen weekday is quiet all day. The example is the range 18:00 to 9:00 with Saturday and Sunday. The other reading (the range applies only on the chosen days) cannot express the example. The range includes its start and stops just before its end. A start after the end crosses midnight. The same start and end give no daily range, so you can use the days alone. Quiet hours use the local time of the computer. A new account has quiet hours off, 22:00 to 07:00, and no days.
- **Snooze is saved.** The configuration has a new top-level field `snooze` (`null`, or `{ "until": <ms since 1970> }`, or `{ "until": null }` for "until I turn it off"), so a snooze still runs after a restart. A timer clears it at its end, so the menus and the configuration window update. "8:00 tomorrow" is 8:00 local time on the next calendar day, also when you choose it after midnight, because the spec says "tomorrow".
- **New configuration fields.** Each account has `notifications` (`{ "new-mail", "calendar", "chat" }`, all `true` by default) and `quietHours`. The version stays 1. A file from phase 04 has none of the new fields, and Shifted reads it with the defaults. A missing switch is on.
- **The set of seen messages.** It holds every entry ID that Shifted saw for the account while it runs, and it never drops an ID. So a message that leaves the feed and comes back (for example, marked read and then unread) does not show again. The first good read after Shifted starts, after a sign-in, after a sign-out, and after the feed of the account changes ("Unread count source") only fills the set. A failed read does not change the set. Snooze, quiet hours, and the switches do not change the set either, so a message that they stopped never shows later.
- **The text of a new-mail notification.** The title is the nickname, else the address. The body has two lines: the sender name (or the sender address if the feed gives no name), then the subject (or "(no subject)"). The notifications of one read show in the order of the feed. More than 3 new messages give one notification with the body "5 new messages" (with the number). A click on that summary opens the inbox of the account.
- **The link of a feed entry.** Shifted reads the `link` of the entry relative to the URL of the feed, and changes `http:` on `mail.google.com` to `https:` (`gmailMessageUrl` in `google-urls.ts`). If the link is empty or not a Gmail link, Shifted opens the inbox. A click loads the link in the Gmail view, which loads Gmail again. This build had no real Google account, so nobody checked yet that Gmail opens the message from this link. Manual test 2 checks it. If Gmail shows the inbox and not the message, write that fact here.

## Phase 07: shortcuts and background

- **Ctrl+, on Windows and Linux (a known exception, chosen by the person).** Gmail's list of keyboard shortcuts has "Ctrl + ," for "Advance to previous chat or compose". The shortcut table of `PRODUCT.md` has Cmd+, for the configuration window, which is Ctrl+, on Windows and Linux. This breaks the rule "No shortcut of Shifted uses a key that Gmail or Calendar already uses". The build stopped and asked. The person chose to keep the table as it is: on Windows and Linux, Shifted takes Ctrl+, from Gmail. On macOS, Gmail lists only Ctrl + , and Shifted uses Cmd+,, so nothing is taken. The unit test of Gmail keys (`test/unit/shortcuts.test.ts`) allows exactly this one exception and stays strict for every other key.
- **The shortcut table** is `SHORTCUTS` in `src/main/shortcuts.ts`, with `CommandOrControl` for Cmd. The app menu now spells the accelerators of Settings and "Snooze notifications…" as `CommandOrControl+,` and `CommandOrControl+Shift+S` (they were `CmdOrCtrl`). This replaces the spelling of the phase 02 and phase 05 choices.
- **Where the keys are caught.** Shifted catches the shortcuts in the `before-input-event` handler of every web contents (`app.on('web-contents-created')`): the Google views, the child windows, and also the screens of Shifted, for example the frame view, the configuration window, and the sign-in window. The app menu applies to every window anyway, so a shortcut does the same thing wherever the focus is. macOS does not reliably give Ctrl+Tab to a menu item, and the frame view blocks Cmd+R (`watchWindowShortcuts`), so catching the keys there also makes those shortcuts work when the focus is in the frame view.
- **How a key matches.** The modifier keys must match exactly. A digit matches by its place on the keyboard (`code`), because Shift changes the character of a digit key (Shift+2 gives `@`). A letter, `,`, and Tab match by the character (`key`), so that they follow the keyboard layout like the app menu. Only a key press counts, not a key release. A held key repeats only "next account" and "previous account". A repeated Cmd+Shift+N starts no second add-account flow.
- **The menus.** The View menu has Reload, Gmail, and Calendar. A new Accounts menu has Add account, Next account, Previous account, and one item for each place from 1 to 9, named after the account at that place. A place with no account shows "Account N" and is off, so the menu shows all the keys.
- **What the actions do.** With no selected account, Ctrl+Tab selects the first account and Ctrl+Shift+Tab the last one. A shortcut in a child window or the configuration window changes the main window but does not bring it to the front. Only Cmd+Shift+N brings the main window to the front, because the content area shows "Signing in…". Cmd+R reloads the Google app that the content area shows, also when the focus is in a child window. It does nothing when the content area shows a panel, for example "This account is signed out.".
- **End-to-end tests press keys with `webContents.sendInputEvent`.** A test on Electron 45 showed that Playwright's keyboard (Chrome DevTools Protocol) does not go through `before-input-event`, and `sendInputEvent` does, like a real key.
- **"Background loading" is saved** as `general.backgroundLoading` (`everything`, `calendars-only`, or `selected-account-only`) in `config.json`. The version stays 1. A file from phase 06 has no field, and Shifted reads it with the default, `everything`.
- **Loaded means loaded at once.** The Google apps that must stay loaded (the table in `PRODUCT.md`) load at startup and whenever the selection, the sign-in state, or the value changes, also if they never showed. So "Everything" loads Gmail and Calendar of every signed-in account at startup, which also gives Calendar reminders from every account. With "Selected account only", both Google apps of the selected account load, so its Calendar reminders work while Gmail shows. This replaces the phase 02 choice "Views are made when they show". Accounts that are not signed in load nothing.
- **When a Google app starts its sleep timer.** Each loaded Google app that must not stay loaded gets a 5-minute timer. Its timer starts when it leaves the set of apps that stay loaded, for example when you select another account. A view that loads outside the set, for example Gmail after a sign-in, also gets a timer. A change of the value applies at once: the apps that must stay loaded wake now, and the other apps start their timers now. They do not sleep at once.
- **A Google app with a child window does not sleep.** A child window closes with its opener page, so sleep would close a pop-out compose window. If the account has an open child window when the timer ends, a new 5-minute timer starts.
- **Asleep shows nowhere.** A Google app that is asleep has no view. Opening it (a tab, the sidebar, a shortcut, a link, a notification, or a `mailto:` link) makes its view again with its first page or the URL of the request. The feed polling does not depend on views.
- **Test timers.** In test mode only, `SHIFTED_TEST_SLEEP_MS` replaces the 5 minutes, and `SHIFTED_TEST_READ_INTERVAL_MS` replaces the time between two reads of the feed, with no random delay (`src/main/test-hooks.ts`). The end-to-end tests of this phase use 1.5 seconds and 1 second.
- **Close and quit.** Closing the main window hides it on every platform. A main window in full screen leaves full screen first, because a hidden full-screen window leaves a black screen on macOS. `window-all-closed` does nothing, so Shifted keeps running. Quit (the app menu, Cmd+Q, or the tray menu) sets a flag that lets the main window close, stops the feed polling, the sleep timers, and the snooze timer, and destroys the tray icon. During quit, a page that asks to stay open (`beforeunload`) does not stop the quit.
- **The macOS Dock.** `activate` shows the main window and brings it to the front. A second copy of Shifted and a click on a notification do the same.
- **The tray icon** (Windows and Linux) is the app icon at 32 by 32 pixels, shown at 16 by 16 points. Its badge is the badge of the Windows overlay (phase 04), drawn in code at 24 pixels on the bottom-right corner, with "99+" for more than 99. A count of 0 shows the plain icon. The tooltip is "Shifted", or "Shifted: N unread". The menu is Show, Snooze (the snooze choices and "Stop snooze", as in the app menu), and Quit. macOS has no tray icon, because the Dock badge shows the total.
- **Linux without a tray.** Shifted asks the session bus whether `org.kde.StatusNotifierWatcher` has an owner (`gdbus call … NameHasOwner`, at most 2 seconds), because Electron on Linux shows tray icons through StatusNotifierItem. If the answer is no, or `gdbus` cannot run, Shifted makes no tray icon, and closing the main window quits Shifted. Desktops that show only the old XEmbed tray count as having no tray.
- **The window position file.** Shifted saves the size and position in `window-state.json` in the user data folder, not in `config.json`. They are not configuration, and a broken window position must never make the configuration file broken. Shifted saves 0.5 seconds after the last move or resize, and at once when the window hides or closes. It saves the bounds that the window has when it is not maximized, and whether it is maximized. A minimized or full-screen window is not saved.
- **"Off every screen"** means that no screen's work area holds a part of the window that is at least 100 by 40 points. Then Shifted centers the window on the main screen, with the saved size made no larger than the work area of the main screen and no smaller than the minimum size.
- **"Open at login" is saved** as `general.openAtLogin` (off by default) in `config.json`, and Shifted changes the operating system only when you turn the switch on or off. If you remove the login item in the settings of the operating system, the switch does not know it.
- **How Shifted knows that it opened at login.** On Windows and Linux, the login item gives the argument `--opened-at-login`. On macOS, `app.getLoginItemSettings().wasOpenedAtLogin` says it. Then the main window starts hidden. It still loads, and the feeds start at once. On Linux with no tray, a second start of Shifted shows the window.
- **The login item on each platform.** macOS: `app.setLoginItemSettings({ openAtLogin })`. Windows: the same, with the path of the executable and the argument (in development, the Electron executable and the app folder, as for `mailto:`). Linux: `~/.config/autostart/shifted.desktop` (`$XDG_CONFIG_HOME/autostart` when it is set). Its `Exec` runs the AppImage file (`$APPIMAGE`) when Shifted runs as an AppImage, because the executable of an AppImage is in a temporary folder.
- **Test mode never changes the login items.** In test mode, the switch only records the value in `globalThis.shiftedTestRecords.openAtLogin`, like "Make Shifted the default email app". On macOS, a development build would register Electron.app, so manual test 6 needs a build from `npm run build:unpack`.

## Phase 09: hardening

- **The security review** is the table in `docs/security-review.md`. Every rule has the status "done".
- **The fuses.** `electron-builder.yml` sets them with `electronFuses`. It also sets `resetAdHocDarwinSignature`, because flipping a fuse breaks the ad hoc signature of an unsigned build for Apple silicon. `EnableCookieEncryption` is a one-way change: a packaged build encrypts its cookies, and a later build without the fuse cannot read them. The fuse `GrantFileProtocolExtraPrivileges` stays on, because the screens of Shifted load from `file://` and need it for their module scripts. The spec does not list it.
- **No remote debugging port.** A packaged build (`app.isPackaged`) removes the switches `--remote-debugging-port`, `--remote-debugging-pipe`, and `--remote-debugging-address` at the start of the main script. - **The certificate message.** "Failure states" says that Shifted blocks the page and shows a message. In the content area, the message is a panel: "Shifted blocked this page. The sign-in window and the child windows have no content area, so they show a native message box with the host of the page.

## CI on three platforms

The first run of `.github/workflows/test.yml` on GitHub found end-to-end failures that this Mac does not show. Prompt 09, section 7, says to fix each failure that only one platform shows. Each choice below names the cause, and whether the fix is in Shifted or in the test.

- **Closing the main window on Linux with no tray (Shifted).** The `close` handler of the main window prevented the close and then called `app.quit()`. Electron cancels a quit when a window cancels its close, so Shifted kept running with a hidden main window and nothing could show it again. Under `xvfb-run` there is no tray, and the test waited for the quit until its time limit. Shifted now calls `app.quit()` with `setImmediate`, after the `close` event ends. The test is unchanged: on Linux with no tray, it still waits until Shifted quits.
- **Controls that show the saved value (test).** The color swatches, "Open at login", and "Ask where to save each file" show the value that the main process saved. A click sends the change, and the control changes when the new state comes back. Playwright's `check()` reads the state right after the click, so it failed when the round trip was slower than on this Mac. The tests now click and then wait with `toBeChecked()`, as the test of "Ask where to save each file" already did. Shifted is unchanged.
- **The sign-in window on a small screen (test).** The macOS and Windows runners have a 1024 by 768 screen. The work area is 677 points high on macOS (menu bar and Dock) and 720 on Windows (taskbar). The operating system makes a window that does not fit as tall as the work area, so the content of the sign-in window was 645 or 681 points high. Shifted still asks for 480 by 720. The test now expects a height of 720, or, on a screen that is too small, the work area less the title bar and the frame. On a large screen, it still checks 720. macOS fits the window to the screen when it shows, so the test measures the window after it shows.
- **The saved size and position of the main window (test).** The test put the window at 140, 120 with a size of 1000 by 700, which does not fit on the 1024 by 768 screen of the macOS runner, and macOS moved it. The test now picks a place inside the work area of the main screen: 40 and 30 points from its corner, 1000 by 700 or smaller (not below the minimum size of 900 by 600). That place is never the default place.
- **The microphone test on a computer with no microphone (test).** The Windows and Linux runners have no microphone, so Chromium answered `NotFoundError` before it asked for permission. The test now starts Shifted with Chromium's switch `--use-fake-device-for-media-stream`, which gives every computer a fake microphone. The permission request still goes to Shifted, and the test still denies it, so nothing reaches the operating system.
- **Download notifications on Linux (CI computer).** Electron shows notifications on Linux with the libnotify library. Every Linux desktop has it, but the Ubuntu runner does not, so `Notification.isSupported()` was false and Shifted showed no "Download finished" notification. The workflow now installs `libnotify4` with Xvfb and D-Bus.
- **A maximized main window when Shifted opens at login (Shifted).** On the 1024 by 768 screen of the macOS runner, a new main window fills the work area, and macOS saves it as maximized. At the next start, Shifted called `maximize()` on the hidden main window, and `maximize()` also shows a window. So Shifted opened at login showed its main window. Now a window that starts hidden maximizes when it first shows, and the size and position are not saved before the window first shows, so the saved "maximized" stays. A new end-to-end test starts Shifted at login with a saved maximized window: the window stays hidden, and the saved state is the same after Shifted quits. After the merge, the `show` event of the main window did not come on the Mac of the person, so Shifted saved no size and position at all. Now a window that is visible at the time of a save also counts as shown. The test does not check `isMaximized()`, because Xvfb has no window manager, and with no window manager a Linux window cannot maximize.
- **Removing an account on Windows (Shifted, approved by the person).** On Windows, Chromium keeps files of the session of an account open while Shifted runs (for example `Network\Cookies`, `DIPS`, `Local Storage\leveldb`, and `WebStorage\QuotaManager`), and Electron has no call that closes a session. Windows does not delete an open file, so the delete of the folder failed with `EBUSY` after about 11 seconds of retries, and the account stayed in the sidebar until then. The person approved this rule, and the coordinator adds it to prompt 01 in the spec repo: on Windows, Shifted clears the storage data of the session at once and removes the account from the configuration at once. It tries the delete of the folder once, with no retries. If the delete fails because a file is in use (`EBUSY` or `EPERM`, or `ENOTEMPTY` for a folder that still holds such a file), Shifted writes the folder to `sessions-to-delete.json` in the user data folder (`src/main/session-folders.ts`). At the next start, before any session opens, Shifted deletes those folders and the list. It deletes only folders inside the `Partitions` folder of the user data folder, also if the list was changed by hand. On macOS and Linux, Shifted deletes the folder at removal, as before. The end-to-end tests of Remove check the folder with `expectSessionFolderDeleted`: on macOS and Linux, the folder is gone at once; on Windows, the test quits Shifted, starts it again, and then checks that the folder is gone.

## Fix after the first real sign-in (2026-10-21)

The person signed in to a real Gmail account and reported three problems. This section deviates from prompt 01 §5 rule 1. The person asked for the fix.

- **The bug.** Right after sign-in, the content area said "This account is signed out." with "Sign in again". But the unread badge of the account showed a number, so the feed, with the same session, worked. The account was signed in.
- **The cause.** Prompt 01 §5 rule 1 says: if the Gmail view tries to go to `accounts.google.com`, stop the navigation. Phase 01 built that literally: `link-handlers.ts` stopped every main-frame `will-navigate` and `will-redirect` to the sign-in host and said "signed out". But a signed-in Gmail session also passes through `accounts.google.com`. Examples: the ServiceLogin, CheckCookie, and SetOSID redirects that set the cookies of `mail.google.com` on the first load of Gmail after sign-in, and the periodic cookie refresh. Phase 01 named this risk (see "Signed-out check" above). The rule cannot work as written with real Google.
- **What stays.** The product rules of `PRODUCT.md` stay: Shifted never shows Google's sign-in page in the content area, and if Google signs an account out, the content area of that account says so.
- **What Shifted does now.** `src/main/sign-in-check.ts` decides, for each Gmail view, Calendar view, and child window of an account (`link-handlers.ts` applies it where it applied the old check):
  1. A main-frame redirect through the sign-in host is no longer stopped. Neither is a navigation to it.
  2. When a main-frame redirect, a navigation start, or a commit goes to the sign-in host, Shifted hides the page at once, so Google's sign-in page never shows. The content area says "Loading…" in its place. A child window hides its window.
  3. When the page commits a page that is not on the sign-in host, for example Gmail again, the page shows again. A feed answer that comes later is ignored.
  4. Only a page that stops on the sign-in host can mean a sign-out. When the page commits a page of the sign-in host and is still there 3 seconds later, Shifted reads the "Whole inbox" feed of the account, once for each check. The feed is not read while the page only passes through: after a restart, the feed of a signed-in account answered HTTP 401 until Gmail had its cookies again (see "The feed during the redirects" below). If the feed says "signed out" (HTTP 401 or 403, or redirects through the sign-in host that do not end with a feed) and the page is still on the sign-in host, Shifted stops the page, loads `about:blank` in it, and shows the signed-out panel, as before.
  5. The feed works: Google refreshes the cookies. Shifted lets it finish while the page is hidden. If the page is still on the sign-in host after 15 seconds, Shifted loads the first page of the Google app once. If that load lands on the sign-in host again (a committed page), or is still there after another 15 seconds, the account is signed out. A child window has no first page, so it closes. So Shifted never loops.
  6. The feed fails for another reason (offline, another HTTP error, or no answer in 15 seconds): the account is signed out only if the page is still on the sign-in host after 15 seconds. Shifted does not restart the page.
  7. A page of an account that is not signed in (signed out, signing in, or not signed in yet) still never goes to the sign-in host: Shifted stops the navigation, as before.
- **The feed itself.** The first run of this fix with the real accounts of the person showed the same problem in the feed reader. `readFeed` said "signed out" for any feed request whose redirects passed through the sign-in host, even when the redirects ended with a feed. Google sends a signed-in feed request through `accounts.google.com/ServiceLogin` when it sets the cookies of Gmail. So all four accounts showed as signed out a few seconds after the start. Now a 200 answer with a feed always means "signed in". "Signed out" means HTTP 401 or 403, or redirects through the sign-in host that do not end with a feed.
- **The feed during the redirects.** The second test run with the real accounts of the person showed that the feed of a signed-in account can answer HTTP 401, with no redirect, while Gmail passes through the sign-in host to get its cookies again. The four accounts of the first build had stale cookies, because the old rule had stopped Google's cookie refresh. Their feeds answered 401 at start, and 200 after Gmail loaded under the new check. After one more restart, all five accounts answered 200 at once, and no account showed as signed out. So the check reads the feed only after the page stopped on the sign-in host for 3 seconds. The spec gives no time. 3 seconds is long enough for a page that goes back by a script.
- **15 seconds.** The spec gives no time. 15 seconds is long enough for Google's redirects on a slow network, and short enough that a person does not wait long. An end-to-end test makes it shorter with `SHIFTED_TEST_SIGN_IN_CHECK_MS`.
- **A line in the console.** When Shifted decides "signed out" from a page, it writes one line to the console of the main process, for example `Shifted found account <id> signed out: its gmail page went to accounts.google.com/ServiceLogin`. The line has the host and the path of the URL, with no query string and no cookies, so a later report shows which Google page caused it.
- **Test mode.** The fake sign-in path (`<server>/signin` and below) stands in for `accounts.google.com`, as before. The fake server imitates the cookie hop of a signed-in session: `/gmail/?hop=redirect` redirects to `/signin`, which redirects straight back to `/gmail/`. `/gmail/?hop=script` and `/gmail/?hop=meta` go to `/signin/check-cookie`, a page on the fake sign-in path that goes back to `/gmail/` by script or by meta refresh. `/gmail/?hop=stuck` goes to the same page, which never goes back. `state.signInHops` counts the hops.
- **The avatar of the selected account.** The screenshot showed an empty ring: no photo and no letter. The ring is empty when the avatar has a saved photo that does not show. The test environment could not reproduce the photo of the person. Two changes make sure that the letter shows in that case, for every account, also the selected one (`PRODUCT.md`, "Accounts in the sidebar"). The avatar shows the first letter on the account color when the saved photo does not load (`onError` of the image). Shifted also does not save a downloaded photo whose pixels are all transparent (`src/main/photo-pixels.ts`).
- **The address in the top row.** On macOS the address at the right end of the top row was cut off by the right edge of the window. The title area now anchors both of its ends with `max()`: it starts after the folder tabs (x 276) and ends 16 from the right edge, inside the free part of `titlebar-area-x` and `titlebar-area-width` on Windows and Linux. The old area took `left` and `width` from those values, so it could go past the right edge whenever the two values do not add up to the window width. A long address ends with an ellipsis inside the area. The address has a tooltip (`title`) with the whole address, and it takes the mouse for that tooltip, so it is not part of the drag region. The test environment showed no cut-off at the default sizes. The end-to-end test checks the edge and the ellipsis at the minimum window width.

## Context menu of a page (2026-10-22)

The person reported that a right-click in Gmail did nothing. Electron shows no context menu of its own. The spec repo now has the section "Context menu of a page" in `PRODUCT.md` and section 7 of prompt 03. Shifted follows them.

- **Two modules.** `src/main/page-menu-items.ts` makes the items and needs no Electron at run time, so that `test/unit/page-menu-items.test.ts` can test it. `src/main/page-menu.ts` handles the `context-menu` event and shows the menu with `Menu.popup`.
- **Where the menu shows.** The Gmail view and the Calendar view (`account-views.ts`), each child window (`child-windows.ts`), the page of the sign-in window (`sign-in-window.ts`), and each screen of Shifted (`lockShiftedScreen` in `shifted-screens.ts`). The account menu of the sidebar stays as it was, because the sidebar stops the right-click itself.
- **The labels** are in sentence case, like the other menus of Shifted: "Open link in browser", "Copy link address", "Paste and match style", "Select all".
- **"Open link in browser"** opens the URL of the link as it is, also a link through Google's redirect page, so that Google's link check still runs. This is the same choice as for a click (phase 03).
- **"Copy email address"** copies the address of a `mailto:` link without `mailto:` and without the subject. A `mailto:` link gets no "Open" item, because a click opens a new message in Gmail of the same account.
- **"Save image"** calls `webContents.downloadURL`. So the image goes to the Downloads folder like an attachment, or to a save dialog when "Ask where to save each file" is on. The label has no "…", because by default no dialog shows.
- **"Look up"** shows on macOS only, for selected text. The label shows at most 30 characters of the selection. The other platforms have no dictionary panel.
- **Spelling.** The menu shows at most 5 suggestions, and "No spelling suggestions" when Chromium has none. "Add to dictionary" calls `session.addWordToSpellCheckerDictionary`. On macOS, the word goes to the dictionary of the operating system.
- **On macOS, a right-click on a word selects it.** So a link and a word of a message also get "Copy" and "Look up". This is how other macOS apps behave.
- **No Back, Forward, Reload, or Inspect.** Shifted is not a web browser. Cmd+R reloads the Google app. A right-click on an empty place shows no menu.
